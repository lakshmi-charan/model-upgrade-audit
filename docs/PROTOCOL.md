# PROTOCOL — confirmatory study (frozen before any main-set episode; see FREEZE.json)

Working title: **Better on Average, Broken in Places: A Repeat-Aware Audit of What Changes When an Agent's
Model Is Upgraded**
Target venue: NeurIPS 2027, Datasets & Benchmarks track.

## Data
- Testbeds (code-graded only): clinical (MedAgentBench FHIR + hazard stress suite), ops (real services:
  PostgreSQL, Gitea, Mailpit, Redis, SeaweedFS, TigerBeetle; fault-free world), mlops (pipeline diagnosis with
  re-execution tools).
- Confirmatory sets (disjoint from pilot and smoke sets; sized to the budget from measured smoke costs):
  clinical `main` = 100 tasks (64 conditional; 49 with no licensed write) · ops `main50` = 50 tasks (seeded
  stratified subsample of `main`, 6–7 per template T1–T8, fault-free world) · mlops `main40` = 40 cases (seeded
  stratified subsample of `main` by domain × oracle type). Seed 20261007 for the subsamples.
- All 11 models (7 pairs) run on every testbed; Gemini models run last (free tier, best effort).
- Projected spend (measured per-episode costs): clinical ≈ $3.1, ops ≈ $1.6, mlops ≈ $1.6; job caps $3.4 / $1.9 / $1.9.
  The pilot set (clinical, 60 tasks) is reported separately as exploratory.
- Upgrade pairs (old → new, same family):
  P1 gpt-4.1-nano → gpt-5.6-luna (provider's official replacement) · P2 gpt-5-nano → gpt-5.6-luna (official) ·
  P3 gpt-4.1-nano → gpt-5-nano · P4 qwen3-30b-a3b-2507 → qwen3.5-35b-a3b · P5 mistral-small-3.2 → mistral-small-2603 ·
  P6 gemma-3-27b → gemma-4-31b · P7 gemini-3.1-flash-lite → gemini-3.5-flash-lite (free tier; best effort).
- Each model: k = 3 independent runs per task, temperature 0, one pinned serving provider (config/models.yaml).

## Hypotheses and primary analyses
- **H1 — one-shot regression reports are mostly noise.** Among tasks the old model passes 3/3 and the new
  model fails in run 1 ("single-run regressions"), the share that the new model passes in run 2 or 3 is > 50%.
  Pooled over pairs and testbeds; 95% CI by task-level bootstrap (10,000 resamples); H1 holds if the lower bound > 0.5.
- **H2 — reliable regressions exist but are rare.** RNF = old 3/3 pass and new 0/3 pass. Per pair × testbed:
  within-task label-permutation test (10,000 permutations), Holm-adjusted across cells. "Exist": ≥ 1 cell with
  adjusted p < 0.05. "Rare": pooled RNF rate among old-reliable tasks has 95% upper bound < 10%.
- **H3 — upgrades change unlicensed actions, in a family-specific direction.** Overreach = a write outside the
  licensed set (clinical: a POST of a resource type the reference does not order, or more POSTs than licensed;
  ops: extra or collateral effects found by the service-side scan). Per pair: paired comparison of per-task overreach
  rates (mean over 3 runs) on clinical tasks whose licensed write set is empty (read-only and
  condition-false tasks) and on all ops tasks, two-sided Wilcoxon signed-rank test,
  Holm-adjusted across pairs. H3 holds if ≥ 2 pairs change significantly and not all significant changes share a
  sign. (Exploratory pilot: decreases for OpenAI/Qwen/Mistral, increases for Gemma/Gemini.)
- **H5 — better on average, broken in places.** In ≥ 2 pairs whose mean success improves (paired bootstrap CI above
  0), RNF is significant (H2 test). Reported per pair with the RNF taxonomy.
- **H4 — re-running failures removes false alarms cheaply.** Procedure "rerun_fail" (run once; re-run failures up
  to 2 more times; flag 0/3) vs "oneshot": false alarms eliminated by construction; extra episode cost reported with
  bootstrap CI; H4 holds if the mean extra cost ≤ 25%. Secondary: first-action probing (FlipScout) cost vs rerun_fail.
- Secondary/descriptive: failure taxonomy of RNF (interface, unrequested_write, wrong_write, missing_write,
  answer_format, wrong_answer); aggregate success change vs RNF count across cells (Spearman); per-template patterns.

## Exclusions and integrity
- Episodes lost to provider/API errors are not recorded (logged in api_errors.jsonl) and re-run; a task enters a pair's
  analysis only with all 3 runs for both models. Exclusion counts are reported.
- Grading uses only code (reference solver, service-side state, pipeline oracle). No model judges anything.
- Every number in the paper is generated by scripts from saved episode files.
- Changes after freezing are listed below with dates and reasons, and results under both versions are reported if
  any change could affect a confirmatory test.

## Amendments after freeze
- 2026-10-08T11:12:11Z — **Added hypothesis H6 (formed on clinical main data, so exploratory there; confirmatory on ops and mlops).**
  Observation on clinical main: in Gemma 3→4, Gemini 3.1→3.5 Flash-Lite and Qwen3→Qwen3.5 the mean drop is carried by
  tasks that the old model passed 3/3 becoming flaky (1–2/3), not by reliable negative flips.
  **H6 — upgrades erode reliability more than they break tasks.** Statistic per pair × testbed: net loss of
  always-passing tasks = #(old 3/3, new <3/3) − #(new 3/3, old <3/3); one-sided within-task permutation test
  (4,000 permutations, seed 0), Holm across the cells of a testbed. Confirmatory test on ops main50 and mlops main40:
  H6 holds if ≥ 2 pairs show significant erosion (Holm p < 0.05) in at least one of those two testbeds, and across
  all testbeds erosion-significant cells outnumber RNF-significant cells.
  Status of data when this was written: clinical main analysed; mlops main40 paid runs collected but NOT analysed
  (no flip/erosion statistics computed on them); ops main50 in progress, not analysed. Script: analysis/transitions.py.

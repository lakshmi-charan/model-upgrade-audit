# Related Work {#sec:related}

**Regression under model updates.** Backward compatibility of model updates was first framed for human–AI teams, where a more accurate update can still break the user's mental model of when the system is right [@bansal2019updates]. *Negative flips*, instances the old model handled and the new one does not, were defined for image classifiers [@yan2021pct] and NLP models [@xie2021regression], and reduced through training-time constraints, distillation or gated fusion of old and new predictions [@yan2021pct; @lai2023gated; @flipguard2024]. For large language models, MUSCLE showed that task adapters suffer negative flips when the base model changes [@echterhoff2024muscle], and API snapshots of the same commercial model were found to drift substantially within months [@chen2023chatgpt]. Two 2026 studies are closest to ours. @cacioli2026beyond applies repeated sampling and a reliable-change index to multiple-choice benchmarks and finds that single-shot evaluation misclassifies many items as changed. @sheng2026nouniversal study sample-level regressions across six same-family upgrade pairs and find that no single signal predicts which samples will regress. Both work with single-turn questions. We study multi-step agents whose failures are actions on real systems, separate reliable flips from run-to-run churn with a permutation test, and classify what kind of action changed.

**Migrating applications across models.** Regression testing of applications built on evolving LLM APIs was argued for by @ma2023prompt, and supported by interactive tooling that diffs old and new outputs [@dixit2024retain] and by regression suites for code models [@abbassi2025recatcher]. Prompt-transfer methods adapt prompts from one model to another [@wang2025promptbridge]. A mining study of open-source applications found that most migrations off retired models happen after the shutdown date [@kim2026retires], and governance proposals call for compatibility gates before updates reach production [@chishti2026testbeforedeploy]. These works motivate our question but do not measure agent-level behaviour under repeated execution.

**Reliability and noise in agent evaluation.** Agent benchmarks report large run-to-run variation: τ-bench introduced pass^k [@yao2024taubench], @rabanser2026reliability propose a family of reliability metrics, and recent measurements show that tool-call sequences and arguments diverge across identical runs [@yagubyan2026consistent] and that within-configuration noise can exceed the gap between model versions [@arino2026identical]. Statistical tools for comparing models efficiently include paired tests for degradation [@kubler2026worse], active testing [@kossen2021active] and anytime-valid sequential evaluation [@hsu2026sequential; @arviv2026stopguessing]; PACE applies sequential testing to accepting self-modifications of an agent [@shawn2026pace]. Process-level evaluation of evolving enterprise agent skills across model changes appeared concurrently [@vo2026process]; it diagnoses deviations on two skills without old-to-new pairs or noise control. Our contribution is complementary: a repeat-aware audit of real same-family upgrades on three executable testbeds, which quantifies how much of what a one-shot regression suite reports is noise.

**Unrequested actions by agents.** Agents that act beyond their mandate have been studied as over-authorization in tool calling [@zhang2026overact], out-of-scope actions by coding agents [@qu2026overeager] and scope adherence in offensive-security agents [@caldwell2026scopebench]; mitigations derive permissions or policies from the user's request [@shi2025progent]. These works compare models at one point in time. We measure how unlicensed side-effecting writes change *across generations of the same family*, on tasks whose licence depends on the state of the world (an order is correct only if a lab value meets a condition).
